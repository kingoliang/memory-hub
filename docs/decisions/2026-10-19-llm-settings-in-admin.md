# 决策：蒸馏 LLM 在管理界面里配置（保存即生效，无需重启）

日期：2026-10-19 · 状态：已采纳 · 影响：设置页、`src/config.js`、`src/admin/settings.js`、`src/server.js`、管理接口两条新路由

## 背景

LLM（蒸馏、经验闸门 strict 模式、图谱蜘蛛 AI 汇总）原来只能通过环境变量 `MEMORY_LLM_*` 或配置文件 `memory-hub.json` 配置，
改完必须重启。设置页只**展示**当前值。Launchpad 部署上没配 LLM，管理员在界面上想配却改不了。

## 决策

1. **存哪里：`<MEMORY_HUB_HOME>/llm-settings.json`，权限 0600，原子写入。不进数据库。**
   - 数据库会被自动备份（`backups/`）、会被 `dev-snapshot` 拷到别的机器；key 放进去就跟着到处走。单独文件不会。
   - 权限不是 0600 时忽略其中的 key（与 `memory-hub.json` 同一规则），并告警。
   - 该文件在数据目录里，不在代码仓库里；仓库 `.gitignore` 仍兜底加上文件名。
2. **优先级：环境变量 > 管理界面 > 配置文件 `memory-hub.json`。**
   设置了任一 `MEMORY_LLM_BASE_URL / MODEL / KEY` 环境变量时，界面显示「由环境变量锁定」，保存返回 409 `llm_env_locked`——
   不能出现「界面上改了、实际没生效」的情况。
3. **key 只写不读。** 接口永远不返回 key，只返回「已设置 / 未设置」；保存时 key 框留空 = 保持原值，
   清除 key 要显式勾选。审计日志只记改了哪些字段名，不记值。
4. **地址不许带凭据。** `baseUrl` 必须是 http/https，不得含 `user:pw@`（凭据请放 key）；界面回显时去掉查询串。
5. **保存即生效。** 服务端每次用到 LLM 时按当前配置现建适配器（适配器只是几个闭包，成本可忽略），
   保存后更新内存里的配置，MCP、`/api/ingest`、图谱 AI 汇总下一次请求就用新值。
6. **测试连接。** 「测试」按钮用表单里的值（key 留空则用已保存的）发一条极小的请求，返回耗时与成败；
   失败信息走与蒸馏同一套 key 擦除（`scrubUpstream`）。
7. **只有超级管理员**能看、能改、能测（`ADMINS`）。

## 反面选项

- **存进数据库 config 表**：最省事，但 key 会进每一份自动备份与开发快照，否决。
- **改写 `memory-hub.json`**：那是运维手写的文件，程序改写会覆盖人的改动，且职责混在一起，否决。
- **界面配置优先于环境变量**：运维用环境变量强制配置的场景会被界面悄悄覆盖，否决；改为「锁定 + 明示」。
