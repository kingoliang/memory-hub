# 决策：管理界面多用户登录 + 三级角色（RBAC）

日期：2026-10-19 · 状态：已采纳 · 影响：schema v4、管理认证、全部管理 API、前端登录与导航

## 背景

团队记忆上线后，MCP 侧每个 Agent 一枚令牌、按 owner/team 分层检索，可见性是严格的；
但管理界面**只有一个管理员口令**，任何能登录的人都看得到全库（包括所有人的 `private` 卡）、
能改删任何卡、能发令牌，审计里也全记成同一个 `admin`。`private` 可见性在网页上形同虚设。

原计划接公司 LDAP（参照 BotimMoney/aiops 的 ai-report），实测 Launchpad 工作区到目录服务
（公司 FreeIPA 的内网地址与端口）**TCP 不通**，所以自建用户体系。登录协议做成可替换的
（`authenticateUser`），以后部署到能通内网的机器再接 LDAP 不需要改权限层。

## 决策

### 1. 账号模型

新表 `admin_users`（schema v4，只加表不改旧表）：

| 列 | 说明 |
| --- | --- |
| `username` | 登录名，**同时就是 owner**；与 Agent 令牌的 `--owner` 对齐，网页与 MCP 是同一个人 |
| `team` | 一人一队（多团队会让可见性规则显著变复杂，按需再扩） |
| `role` | `admin` / `lead` / `member` |
| `password_hash` | 复用现有 scrypt 格式与强度 |
| `disabled_at` | 停用即生效：删除该用户全部会话 |

账号**只能由超级管理员建**（不做自助注册）。用户名规则与 owner 一致（`validateParty`）。

`admin_sessions` 增 `user_id` 列：`NULL` 表示「应急管理员会话」。

### 2. 原管理员口令 = 应急（break-glass）入口

保留不变：登录时用户名留空即走它，身份是超级管理员 `admin`。理由：升级后不锁门、零数据迁移；
用户表坏了 / 管理员忘记口令时仍有入口。审计里它记为 `admin`，与具名用户区分开。

### 3. 权限矩阵（服务端强制，前端隐藏只是体验）

| 能力 | member | lead | admin |
| --- | --- | --- | --- |
| 看卡片 / 详情 / 检索 / 图谱 / 蜘蛛 / 标签统计 | 可见范围内 | 可见范围内 | 全部 |
| 编辑 / 软删 / 回滚自己的卡 | ✓ | ✓ | ✓ |
| 编辑 / 软删本团队他人的卡 | ✗ | ✓ | ✓ |
| 待审队列：看 / 审批 | 自己的（只看） | 本团队（可审批） | 全部 |
| 令牌：看 / 建 / 改 / 撤销 | 只限自己的，owner/team 强制为本人 | 同 member | 全部 |
| 用户管理、整理中心、标签批量改、设置、审计日志、活跃度、健康报告、回收站、永久删除 | ✗ | ✗ | ✓ |

**可见范围 = MCP 检索的同一套规则**（`core/scope.js` 的 `tierOf`）：自己的全部 + 本团队
`team`/`public` + 其它团队 `public`；他人 `private` 永远不可见。待审/驳回卡对成员只显示自己的。

### 4. 防漏的机制

最大的风险是**某个接口忘了加检查**。所以：

- **默认拒绝**：路由表每一项必须显式声明 `roles`；缺声明在服务启动时抛错（漏写跑不起来，而不是悄悄放开）。
- **越权矩阵测试**：以三种角色调用**每一个**路由，期望状态码写死；路由表与测试表不一致时测试失败（新增接口必须补测试）。
- **数据级越权测试**：成员对他人私卡的 看 / 详情 / 改 / 删 / 图谱 / 蜘蛛 / 标签统计 全部拿不到。
- 判定集中在 `src/admin/rbac.js`（纯函数），作为变异测试靶区。

### 5. 审计

`write_log.actor_name` 记真实用户名（应急入口记 `admin`）；`actor_id` 仍是会话哈希前缀。

## 影响

- `src/core/db.js`：schema v4（`admin_users` 表、`admin_sessions.user_id` 列）
- `src/admin/users.js`（新）：用户 CRUD 与认证；`src/admin/rbac.js`（新）：角色与可见性判定
- `src/admin/auth.js`：会话带用户；`handler.js`：路由声明角色、登录接受用户名
- `src/admin/queries.js` / `ops.js` / `graph.js` / `spider`：按查看者过滤
- `web/`：登录页加用户名、导航按角色裁剪、新「用户」页
- CLI：`memory-hub user create|list|disable|enable|set-password|set-role`

## 反面选项

- **签名 cookie 无状态会话**（ai-report 的做法）：登出无法服务端撤销、停用用户不能立刻踢下线，否决。
- **把可见性放在前端过滤**：接口照样能直接拿到全量数据，否决。
- **成员也能看全库但只能改自己的**：违背 `private` 的语义，否决。
