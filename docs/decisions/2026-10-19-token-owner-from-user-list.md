# 决策：令牌归属人从账号列表里选，不再手填

日期：2026-10-19 · 状态：已采纳 · 影响：管理界面令牌表单、令牌接口校验、owner 规范化、一次性数据修正

## 背景

多用户上线后，用户名即 owner：网页登录的人和他的 Agent 令牌 `--owner` 必须是同一个字符串，可见性与「自己的卡」都靠它判断。

但令牌的归属人在管理界面里是**手填**的。上线当天就出了事故（Launchpad 实例）：

| | 值 |
| --- | --- |
| 网页账号 | `guoyouma` |
| 令牌 owner | `GuoyouMa` |

两个原因叠加：①人手填，容易错或填成别人；②实现不一致——建账号时用户名转小写，建令牌时 owner 原样保存，比较又区分大小写。
后果：这个人 Agent 写进来的私卡，他自己在网页上看不到；他的卡也不会排在「自己的记忆」那一层。

## 决策

1. **管理界面里选，不填**：管理员建 / 改令牌时，归属人是一个下拉框，选项来自账号列表（未停用的账号）；
   选中后团队**自动带出**账号的团队，不再单独填。
   新接口 `GET /admin/api/users/options`（仅超级管理员）返回 `[{username, team, role}]`，只给下拉用，不含任何敏感字段。
2. **服务端强制**（前端只是体验）：超级管理员经管理界面建 / 改令牌时，`owner` 必须是**已存在且未停用**的账号，
   `team` 一律取该账号的团队（请求里的 team 被忽略）；否则 400 `unknown_owner`。成员仍强制为本人（不变）。
   还允许「无主令牌」（owner 留空）——给不属于任何人的自动化脚本用，仍是单机老语义。
3. **owner 统一小写**：`validateParty` 对 owner 做小写规范化（team 不变，团队名大小写有意义，如 `PayTool`）。
   CLI / stdio 也走同一入口，所以 CLI 手填大小写也不会再错位。
4. **一次性数据修正**（schema v5，只改值不改结构）：`cards` / `quarantine` / `agent_tokens` 的 owner 统一转小写。
   幂等；只影响大小写，不会把两个不同的人合并（大小写不同的同名 owner 本来就该是同一个人）。

5. **团队永远跟着人走**：管理界面里不能单独改令牌的团队（400 `team_follows_owner`）；
   在「用户」页给一个人换团队时，他名下**未撤销**令牌的团队同步跟着变（已撤销的保留历史值）。
6. **创建后当场给接入命令**：令牌明文弹窗里直接给出 Claude Code / Codex / pi 的配置命令（MCP 地址由管理界面 URL 推出，
   令牌已填好），以及 `memory_whoami` 的核对方法——发令牌的人拿到就能用，不用再去翻文档。

CLI `token create --owner` 仍可手填（运维场景，账号可能还没建）；只做小写规范化，不强制账号存在。

## 反面选项

- **只在前端做下拉**：接口照样能传任意 owner，治标不治本，否决。
- **owner 比较改成忽略大小写**：要改所有比较点（SQL、tierOf、rbac），漏一个就是越权口子；统一存小写更简单、可验证。
